# Brokers, MCP and logos

Moved out of the always-loaded CLAUDE.md. Read this when changing broker connections, `broker_oauth.py`, `brokers.py`, `broker_history.py`, `mcp_client.py`, the INDmoney MCP tools, or holding logos.

## Modules

- **`app/broker_oauth.py`**: Generic MCP OAuth 2.1 for brokers that sign users in themselves (Zerodha, FYERS, Upstox, Dhan, Groww): `discover()` (the 401 `resource_metadata`, else well-known), `register()` (DCR), `pkce()`, `authorize_url()`, `exchange_code()`, `refresh()`; https only, `OAuthError` with safe messages (`OAuthRefused` only for `invalid_grant` or HTTP 401; 5xx/429 stay plain `OAuthError`), `expires_in_seconds()` (missing, non-numeric or non-positive gives 3600). Routes `GET /auth/brokers/{id}/connect|callback` (state on the `oauth_sessions` row under `brokerOauth`) store `{accessToken, refreshToken, expiresAt, client, tokenEndpoint}` vault-encrypted in `broker_connections.session`. INDmoney keeps its own flow in `main.py`
- **`app/brokers.py`**: Read-only holdings straight from a broker's MCP server (six brokers with official hosted servers: Kotak Neo `mcp_login_qr` (UCC, link plus QR, `verify_login()`, `session_arg` injects its own login session into every call), Zerodha/FYERS/Upstox/Dhan/Groww `oauth` (Zerodha and FYERS moved from `mcp_login_tool` on 2026-11-17, when their servers began answering 401 with an OAuth challenge; they keep curated lists, which win over the live list; Kite groups its tools by `mode` since 2026-11-17 (`alerts`, `gtt`, `help`, `market`, `mutual_funds`, `orders`, `portfolio`, `session`), so Zerodha has `read_modes` (tool → the only `mode`s `call_broker_tool` passes; `orders` only `list`/`history`/`trades`/`all_trades`) and `holdings_arguments` (`portfolio` `mode=holdings, type=full, limit=500`, `mutual_funds` `mode=holdings`), and `_holdings_items()` follows `next_page()` (`pagination.has_more`) up to `MAX_HOLDINGS_PAGES` (20), else `BrokerDataError` rather than part of the holdings; `tests/login_tool_brokers.py` puts login-tool variants with Kite's old `get_*` tools back for the tests of that flow); `<ID>_MCP_URL` overrides; other OAuth brokers' read tools are `dynamic_read()` over their live `tools/list` (`readOnlyHint` or a `get_`/`search_`/`list_`/`fetch_` name with no write word); `normalise_generic()` for brokers whose layout is not recorded, raising `BrokerDataError` rather than showing zero; `BROKERS` registry, one `Broker` entry plus a normaliser per broker). `read_tools` is an explicit allowlist (`WRITE_TOOLS` can never overlap it); the connection is the broker's MCP session id, vault-encrypted per profile in `broker_connections` (`pending` / `connected` / `needs_login`), `login_url()` accepts only an https link on the broker's `login_hosts`; `start_login()`, `check_status()` (never raises; 12 h session, 5 min login window; `unavailable` leaves the stored status), `oauth_token()` (refreshes serialised per (profile, broker) by `_refresh_locks`, the connection re-read under the lock so a finished refresh is reused, new tokens saved at once; `needs_login` only on `OAuthRefused` while the stored refresh token is still the one sent; other refresh failures raise, so status reads `unavailable`), `fetch_holdings()` (live, else the sealed stored copy with `stale`/`asOf`; stored only when `snapshots_allowed`), `normalise_kite()` (CAS row layout, missing price stays None), `combined()` / `split_indmoney_rows()` (a connected broker's own rows replace INDmoney rows whose broker label contains its `indmoney_labels`, and INDmoney rows with an empty or generic label (`GENERIC_LABELS`) whose `isin_of()` (ISIN-shaped `investment_code`) equals a row of that broker, same asset type; never by name, never another named broker's row; labelled rows whose ISIN the broker lacks are counted in `combined.onlyInIndmoney` and still left out), `needs_attention()` (`needsAttention` and `checkedAt` on `GET /api/brokers` items: `needs_login`, or `connected` with holdings over `HOLDINGS_STALE_MS` old), `export_brokers()` (with `history`), `broker_tools()` (`get_broker_holdings`, `call_broker_tool`; handlers catch everything, never `McpAuthError`, so INDmoney's token refresh is not triggered) and `context_line()`. Presentation: items and combined sources carry `logo` (`logo_path()`: `/brokers/<id>.png`, the brokers' own site icons in `frontend/brokers/`); INDmoney is not in `BROKERS` (its backend stays in `main.py` / `users.indmoney`) but `broker_list()` puts `indmoney_item()` first in `GET /api/brokers` (`auth: indmoney_oauth`, `needs_login` when its stored token expired with no refresh token, `holdingsAt` the latest snapshot; no call to INDmoney) and `indmoney_tools()` / `describe_indmoney_tools()` serve `GET /api/brokers/indmoney/tools` (`read` only for `mcp_client.IMPORTANT_PORTFOLIO_TOOL_NAMES`). Free-plan limit: `plans.Plan.max_brokers` (Free 2, others `None`), `connected_count()` (INDmoney if connected + every registry-broker row in any status), `can_connect()` (already connected, no limit, or under it), `check_limit()` / `BrokerLimitReached` run inside `BEGIN IMMEDIATE` in `save_connection()` and `save_indmoney_connection()` so a race cannot end with 3; `limit_error()` is the 403 body `{error, brokerLimitReached, limit, connected, pricingUrl}`; redirect routes go to `/?brokerError=limit`; a profile above the limit keeps its connections. `GET /api/brokers` returns `{brokers, limit, connected}`; `plans.usage()` adds `brokerLimit` and `brokersConnected`
- **`app/broker_history.py`**: Daily broker holdings history: sealed `broker_snapshots(user_id, broker, local_date, captured_at, data)` rows (rows plus computed `totalInr`, no plain value column) upserted by `store_day()` on every successful stored live `brokers.fetch_holdings` (a failure there never loses the holdings), pruned with the INDmoney snapshots (`snapshots.prune`), deleted by broker disconnect, history clearing and private mode (INDmoney disconnect keeps them; profile deletion cascades), exported under each broker's `history`. `due_connections()` / `refresh_due()` (called from `snapshots.run_scheduler`): consenting `device`-mode profiles' `connected` brokers not captured since the latest `SNAPSHOT_TIME`, sealed with the public key like INDmoney snapshots, a failed try waits an hour (in memory) and an ended login only sets `needs_login`. `combine_day()` (pure `Decimal`): `combinedInr` = INDmoney net worth minus the INDmoney rows `split_indmoney_rows()` drops for brokers with data that day plus each broker's total (latest earlier snapshot within `CARRY_DAYS` 3 marked `carried`; days with brokers only are `partial`; an unreadable net worth, dropped value or broker total gives no value, never 0); `merge_history()` / `with_combined()` add it to `snapshots.networth_history()` points (`GET /api/snapshots` returns `includesBrokers`, `combinedInr`, `combined`; the `get_networth_history` tool adds `combinedInr` and a `combinedNote` only when broker history exists)

- **`app/mcp_client.py`**: MCP session setup, tool calls (INDmoney with a bearer token; a broker with `token=None`), the INDmoney read-only tool allowlist, and `McpHttpError` (a non-2xx other than 401, with `status_code`).

- **`app/logos.py`**: Logos beside holdings. `logo_key()` (`mf:<digits>`, `in:<SYMBOL>` (INDmoney's own rows give its `ind_key`, `in:INDS00021`, not the NSE symbol; a broker's BSE-only stock `in:<SYMBOL>.BO`), `us:<TICKER>`; `holding_key()` prefers a broker stock row's `ticker` (`brokers.stock_ticker()`: its trading symbol without `NSE:`/`BSE:` or `-EQ`, `.BO` for BSE, set by `normalise_kite` / `normalise_generic` on `IND_STOCK` rows and kept by `portfolio_math._holding_metrics`), since those rows' code is an ISIN; ASCII only, `None` for anything else), shared `logos(key, status, file, checked_at)` rows and files under `<APP_DATA_DIR>/logos/` (public images, no profile link: not exported, not cleared with history, not deleted with a profile), `status` `found` / `missing` (retried after 30 days; a 404 is `missing`) / `failed` (retried after 1 day), `download()` (a fresh `httpx.Request` per hop so Host is set; https only, `MAX_LOGO_BYTES` 200,000, PNG/JPEG/WebP by magic bytes, no SVG, no client default headers or auth on any redirect hop, never raises), at most 4 downloads at once per event loop and a lock per key, `fill_fund_logos()` (INDmoney `get_mf_funds_details` `image_url` with that profile's own connection, fund ids batched 10 per call), `fill_stock_logos()` (logo.dev `https://img.logo.dev/ticker/{SYMBOL}?token=...&format=png&size=96&fallback=404`, NSE symbols with `.NS` (BSE `.BO`), US tickers bare, only when `LOGO_DEV_TOKEN` is set; `in:INDS…` keys are first turned into a symbol by INDmoney `get_indian_stocks_details` (`entity_basic.symbol` / `exchange`, recorded live 2026-11-17, 10 per call, `ind_call`; a failed lookup is `failed`, a key without a symbol `missing`, and without an INDmoney call (broker fetches) they are left for the next snapshot); source docs.logo.dev, cited in a comment), `schedule_fill(fund_call=, stock_call=)` (background, after `snapshots.capture_snapshot` and live `brokers.fetch_holdings`; failures logged, never failing the capture), `with_logos(holdings, user_id)` (adds `logo` from cached files only, as `/api/logos/<key>?s=<sig>`: `sign()` is HMAC-SHA256 of `user_id:key` under `vault.derived_key(b"logo-url-v1")` (never the Fernet key bytes), base64url of 16 bytes, so one profile cannot probe whether another holds a ticker; applied in `snapshots.portfolio_figures()` (holdings and `figures.top_holdings`) and `brokers.rows_view(logo_user=)` (only when `fetch_holdings(with_logos=True)` from the page routes or `combined(logo_user=)`; agent tools pass neither); a database error logs `logo_lookup_failed` and returns the rows unchanged), `enabled()` (`LOGOS_ENABLED`). `GET /api/logos/{key}?s=` needs a profile but not unlock, checks `signature_ok()` (`hmac.compare_digest`) against the signed-in profile, serves cached files only (the same 404 JSON for a key `logo_key` cannot produce, an uncached key and a missing or wrong signature) with `Cache-Control: private, max-age=604800` (the `no_store_api` middleware leaves a route's own header alone); the agent's tools return figures only, so `logo` never reaches the model. `logs.configure` sets the `httpx` logger to WARNING so the logo.dev token in a URL is never logged. Frontend: `finance.js` `holdingLogoHtml(item)`; `#/holdings` shows a logo when set, else its tone tile, and `holdingsTable()` a logo or monogram. What INDmoney's `image_url` is (a fund-house or a per-scheme image) is unverified: record it after the first live snapshot

## MCP client

**Tool allowlist** (`mcp_client.py`):
- `IMPORTANT_PORTFOLIO_TOOL_NAMES`: 15 documented read-only INDmoney tools
- `filter_portfolio_tools()` drops anything else the MCP server exposes, including write tools

**MCP session management** (`mcp_client.py`):
- `fetch_mcp_session()`: initialize → notifications/initialized → tools/list
- `_rpc_body()` parses JSON or `text/event-stream` bodies, skipping notifications and joining multi-line `data:` fields
- `call_mcp_tool()` accepts an optional shared `httpx.AsyncClient`

- `McpToolError` (the tool reported an error the model can fix) and `McpAuthError` (HTTP 401 or auth-failure text: refresh the token)

## Routes

- OAuth routes: `GET /auth/indmoney/connect` (requires a profile), `GET /auth/indmoney/callback` (saves tokens on the profile and queues a first snapshot), `POST /auth/indmoney/disconnect`

- Broker routes: `GET /api/brokers` (`{brokers, limit, connected}`; INDmoney first; items carry `auth` and `logo`), `GET /api/brokers/{id}/tools` (the server's tools and which are read-only; OAuth brokers need a connection, else `needsConnection`), `POST /api/brokers/{id}/verify` (Kotak QR), `POST /api/brokers/{id}/connect` (consent + unlocked; Kotak takes `{ucc}`; returns `loginUrl` for the user to open, nothing redirects back; OAuth brokers return `authorizeUrl`), `GET /api/brokers/{id}/status` (polled every 3 s while pending), `POST /api/brokers/{id}/disconnect`, `GET /api/brokers/{id}/holdings?refresh=`, `GET /api/holdings/combined?refresh=` (consent + unlocked); connect, status and refresh use the `broker` rate rule. Portfolio Analyzer works with only a broker connected (no INDmoney token): `stream_agent` skips the INDmoney session when `get_broker_holdings` is offered. Frontend: profile dialog "Brokers" section and `#/holdings` (tabs from `finance.js` `holdingsTabs()`, INDmoney first, each with a `logo`; see Frontend, Holdings; `brokerLogoHtml()` / `monogram()` (24px, `alt=""`, a failed image becomes a letter tile in `app.js`), `brokerConnectBlocked()` / `LIMIT_NOTE`; the profile dialog has no separate INDmoney row: INDmoney is a Brokers row, its Connect/Reconnect go to `/auth/indmoney/connect` and its Disconnect to `/auth/indmoney/disconnect` after the old confirmation, `openBrokers()` opens the dialog for the `data-connect` buttons); reconnect banner (`[data-broker-banners]` on Home and Holdings, one line in the rail via `brokerAttention`, `app.js` `refreshBrokerAttention()`; each connected broker's `GET /api/brokers/{id}/status` at most hourly on load; dismissed for the local day in localStorage; helpers `brokersNeedingAttention()`, `brokerBannerText()`, `brokerReconnectAction()`, `bannerDismissed()`, `brokersToCheck()` in `finance.js`); history charts use `historySeries()` (combined value when `includesBrokers`)
