# Privacy, sealing, sign-in and plans

Moved out of the always-loaded CLAUDE.md. Read this when changing profiles and sessions, Google sign-in, PIN/recovery sealing, the vault, consent and storage modes, the admin page, plans, credits or usage limits. `POLICY_VERSION` history is under "Account sign-in". User-facing description: [../privacy-and-data.md](../privacy-and-data.md).

## Modules

- **`app/main.py`**: FastAPI routes, INDmoney OAuth, and the lifespan task that runs the snapshot scheduler. `POST /api/chat` returns the full answer as plain text with the call trace in an `X-Agent-Trace` header; with `Accept: text/event-stream` (`wants_stream()`) `_stream_chat()` streams progress instead (see `app/chat_stream.py`): `_prepare_chat()` (checks and the daily slot, refusals keep their status codes) then `_run_chat(prepared, on_event)` run in a task kept in `_stream_tasks`, so a browser that goes away never loses the answer or the in-flight guard.
- **`app/db.py`**: `connect_db()` context manager (commits/rolls back, always closes), schema, and migrations. Tables: `users`, `accounts`, `oauth_sessions`, `chats`, `portfolio_snapshots`, `consents`, `cas_statements`, `investigations`, `broker_connections`, `broker_snapshots`, `agent_runs`, `financial_goals`, `financial_decisions`, `goal_allocations`, `page_views`, `question_counts`, `question_reservations`, `amfi_navs`, `benchmark_navs`, `logos` (WAL mode). Columns added to `users` after release go in `_ADDED_USER_COLUMNS`; the `users` columns live in `_USERS_COLUMNS` (shared with `_drop_unique_display_name()`, which rebuilds an older table whose `display_name` was UNIQUE, foreign keys off, in one transaction). A pre-profile `chats` table is renamed `chats_legacy` and adopted on first sign-in.
- **`app/users.py`**: Profiles (scrypt PIN hashes, account-bound lockout), browser sessions bound to profiles, profile fields (`ProfileFields`), and per-profile INDmoney tokens (`user_access_token` refreshes them).
- **`app/accounts.py`**: `AUTH_MODE` (`local` default, `google`), `check_config()` (startup), Google OpenID Connect (`start_sign_in()`, `finish_sign_in()`, `id_token_claims()`, `check_claims()`), the pending Google account on a session (`pending_values()`, `pending_identity()`), and the `accounts` table (`user_for_identity()`, `link()`, `is_linked()`, `account_for_user()`, `unclaimed_profile_named()`).
- **`app/admin.py`**: The operator's admin page (`ADMIN_EMAILS`; every admin path 404s without it): admin Google sign-in on its own `ca_admin` cookie and unbound session row (`is_signing_in()` picks the shared `/auth/google/callback` by `state`, `finish_sign_in()`, `admin_for_session()` re-checks the address and `SESSION_SECONDS` on every request), `overview()` / `profiles()` (only unsealed columns: name, Google email, plan, today's questions, this month's credits via `credits.from_row()` (read-only: never starts or rolls a month) and `totals.creditsUsedThisMonth`, consent, INDmoney connected, snapshot failure, last seen, lockout), `backups` (`backup.status()`) and `model` (`model_gate.status()`: slots, calls waiting, last successful answer per provider since the restart), `clear_lockout()`, `sign_out_everywhere()`. `check_config()` needs a Google client in either `AUTH_MODE`
- **`app/privacy.py`**: The privacy notice (`NOTICE`, `POLICY_VERSION`), consent records, per-profile storage mode and snapshot retention, data export, and history clearing.

- **`app/sealing.py`**: Per-profile X25519 keypairs, wrapping the private key with a PIN or recovery code (scrypt + SecretBox), recovery codes, and `ProfileKeys` (`seal()` / `open()`).
- **`app/unlock.py`**: Key creation, `unlock_with_pin()`, `recover()`, `replace_recovery_code()`, and the in-memory map of unlocked browser sessions (`activate()`, `keys_for_session()`, `forget_session()`, `forget_user()`, `sweep()`: drops keys whose session row is gone, idle past the max age or bound to another profile). `end_all_sessions(user_id)` deletes every session row of a profile and forgets its keys and private chats (recovery, admin "sign out everywhere", profile deletion).

- **`app/vault.py`**: Master key resolution (`APP_MASTER_KEY`, `APP_MASTER_KEY_FILE`, default `~/.config/ca-mode/master.key`) and Fernet `encrypt()` / `decrypt()` for secrets stored in SQLite. A missing key file is created only when `encrypted_values_stored()` finds no `enc:v1:` value in `ENCRYPTED_COLUMNS` (`users.indmoney`, `broker_connections.session`, `oauth_sessions.data`); otherwise `VaultError` naming the file stops startup.

- **`app/page_views.py`**: Anonymous page-view counts: `page_views(day, route, views)` rows only (no profile, session, IP or browser), `Route` literal matching `pages.js` `ROUTE_META`, `record()` (upsert + prune past `RETENTION_DAYS` 90), `counts()`, `totals()`, `is_enabled()` (`PAGE_VIEWS_ENABLED`). Counted only when `snapshots.snapshots_allowed(user)`; not in export, history clearing or profile deletion (not linked to a profile). CLI: `python -m scripts.page_views [--days N] [--daily]`
- **`app/plans.py`**: Plans as data (`PLANS`: `free`, `individual`, `team`; prices shown on `/pricing`, `PRICES_UPDATED`), `plan_of()` (unknown values count as Free), `has_daily_cap()` (Free only), `usage()` (`plan`, `planName`, `limit`, `used`, `remaining`, `resetsAt` for `/api/session`), `set_plan()`, `free_daily_questions()` (this copy's cap, else `FREE_DAILY_QUESTIONS` 10, defined in `limits.py`), `contact_email()` (`PRICING_CONTACT_EMAIL`). No checkout: `python -m scripts.plans list|set <name, Google email or id> <plan>`
- **`app/credits.py`**: Monthly credits for plans with `Plan.monthly_credits` (Individual: 3,000): `TOKENS_PER_CREDIT` 1,000, `credits_for_tokens()` (ceil, at least 1), `tokens_used()` (sum of `promptTokens` + `completionTokens` over `model_result` run events; None when none), `period_bounds()` (month from the plan's start day, clamped to short months), `balance()` / `ensure_available()` (`CreditsExhausted`) / `charge()` (monthly first, then top-ups, never below zero, `BEGIN IMMEDIATE`), `start_plan()` (called by `plans.set_plan()` on a move onto such a plan), `add_top_up()`. State on `users`: `plan_started_at`, `credit_period_start`, `credits_used`, `topup_credits`. `main.chat` checks before `run_agent` (402 `{error, creditsExhausted, renewsOn, pricingUrl}`) and charges an answered question (`X-Credits-Charged`, `X-Credits-Remaining`); a failed charge is logged and never loses the answer. CLI: `python -m scripts.plans topup <profile> <credits>`

- **`app/limits.py`**: Usage limits for a shared copy, each off unless configured: `reserve_question()` (returns a `Reservation`) / `confirm_question()` / `release_question()` (`DAILY_QUESTION_LIMIT` per Free-plan profile per local day; `capped=False` for paid plans in `SNAPSHOT_TIMEZONE`, `question_counts` rows plus a `question_reservations` row per unanswered question, `BEGIN IMMEDIATE`, today and yesterday kept, `DailyLimitReached`; `release_stale_reservations()` gives back slots of requests killed mid-answer: all at startup (lifespan), older than `RESERVATION_TTL_SECONDS` on each housekeeping tick and on the profile's next reservation), `check_rate()` (`RATE_LIMITS_ENABLED`; in-memory `RateLimiter` sliding windows per IP and per profile from `RATE_RULES`: `chat`, `sign_up`, `sign_in` (login, unlock, recover), `investigation`; `RateLimited`), `client_ip()` / `client_address()` (`CF-Connecting-IP` with `TRUSTED_PROXY=cloudflare`, the last `X-Forwarded-For` entry with `TRUSTED_PROXY=caddy`, else the peer; IPv6 grouped by /64), `turnstile_site_key()` / `verify_turnstile()` (both `TURNSTILE_*` keys set; fails closed with `TurnstileUnavailable`)

## Profiles and sessions

**Profiles and sessions** (`users.py`):
- The `indmoney_session` HttpOnly cookie maps to an `oauth_sessions` row whose `user_id` names the signed-in profile; the id rotates on sign-in. `GET /api/session` without a live row stores nothing and sets no cookie (`touch_session()` only updates, returns False for a missing row and deletes one idle past the max age); rows are made by sign-in, sign-up, claim and Google start. `current_user()` forgets the unlocked key of a session that no longer resolves to a profile
- Routes other than `/healthz`, `/api/providers`, `/api/session`, the sign-up/sign-in/claim/sign-out routes, `/auth/google/*` and the admin routes return `401 {"profileRequired": true}` without a profile; admin routes need an admin session instead (`401 {"adminRequired": true}`)
- `check_pin()` reads the lock state from the DB and records the outcome in a `BEGIN IMMEDIATE` transaction, so concurrent wrong PINs cannot bypass the 5-attempt / 5-minute lock
- PIN hashing (scrypt N=2^17) runs via `asyncio.to_thread`; tests lower `users.SCRYPT_N`
- The PIN is a local lock, not network-grade auth; anywhere other people can reach the app, use `AUTH_MODE=google` (below)
- `users.create_user(unique_name=)`: the picker refuses a name in use (checked in `BEGIN IMMEDIATE`); Google mode allows repeats, since refusing would reveal that the name exists

## Account sign-in

**Account sign-in** (`accounts.py`, `AUTH_MODE=google`):
- Needs `GOOGLE_CLIENT_ID` / `GOOGLE_CLIENT_SECRET` (`accounts.check_config()` fails startup otherwise) and `APP_ORIGIN`; redirect URI is `APP_ORIGIN + /auth/google/callback`
- `GET /auth/google/start` stores `state`, `nonce`, PKCE verifier and start time under `accounts.SIGN_IN_KEY` on the session (a fresh session id when not signed in) and redirects to Google with `prompt=select_account`. The callback exchanges the code with the client secret; the ID token comes from the token endpoint over TLS, so its claims (issuer, audience/azp, exp/iat with `CLOCK_SKEW_SECONDS`, nonce, verified email) are checked, not its signature. Failures redirect to `/?signInError=cancelled|expired|failed` (`app.js` `SIGN_IN_ERRORS`)
- A linked account signs in with `users.sign_in()` (rotated id, history still locked until `/api/session/unlock`). An unlinked one gets a fresh unbound session holding `accounts.PENDING_KEY` (`PENDING_SECONDS`, 30 min) until `POST /api/users` (create + link) or `POST /api/account/claim` (name + PIN of a profile no account has claimed; one generic `CLAIM_FAILED` answer, `accounts.spend_pin_check()` for unknown names, wrong PINs count towards that profile's lockout; `ALLOW_PROFILE_CLAIMS=false` returns 403)
- `main.signed_in_user_id()` (used by `current_user()`, `/api/session`, logout and the INDmoney routes) treats a session bound to a profile without an `accounts` row as signed out in Google mode. `/api/session` returns `profiles: []`, `authMode` and `account`; `POST /api/session/login` is 404; `/api/session/recover` resets only the signed-in profile
- `accounts.email` is vault-encrypted; `accounts.subject` (Google `sub`) is plain for lookup and never exported. The link cascades with the profile; export has `account` (`provider`, `email`, times). `POLICY_VERSION` 2026-10-21.1 added the notice section on Google sign-in; 2026-10-22.1 added the stored plan; 2026-10-22.2 added what the admin page shows; 2026-10-26.1 added the calculated figures kept in answer records; 2026-11-06.2 added the stored OAuth tokens of Upstox/Dhan/Groww and Kotak's login session; 2026-11-06.3 added the daily broker holdings history; 2026-11-12.1 added the mutual fund ledger from a detailed CAS (folio numbers replaced by a code) and the daily AMFI NAV download ("Public fund data"); 2026-11-13.1 added the benchmark NAV history from mfapi.in; 2026-11-13.2 added the optional income-tax slab profile field; 2026-11-17.1 added the "Logos" section (tickers to logo.dev, fund ids to INDmoney, shared public logo files); 2026-11-17.2 moved Zerodha and FYERS to stored OAuth tokens; 2026-11-10.1 added daily database backups (where, how many, the master key never copied, deleted data lingering in older copies), Cloudflare Tunnel/Access in front of a hosted copy, monthly credits, the in-progress question marker and credits on the admin page; 2026-11-06.1 added broker connections (the encrypted session id and the latest holdings fetched, sealed; removed by disconnect, history clearing, private mode and profile deletion; export has `brokers`)

## PIN-locked history

**PIN-locked history** (`sealing.py`, `unlock.py`):
- Saved chat titles and messages, snapshot `data` (with the net worth inside; `networth_inr` is NULL) and `users.profile` are `sealed:v1:<sealed box>` under the profile's public key; plaintext rows (profiles that never unlocked since this feature) pass through `ProfileKeys.open()` and are sealed by `unlock.activate()` at the next PIN entry
- `users.history_key_pin` / `history_key_recovery` hold the private key wrapped as `scrypt$N$r$p$salt$box`; `history_public_key` is plain so the scheduler can seal without a PIN
- `main.current_user()` attaches `user["keys"]`; `history_gate()` returns `403 {"unlockRequired": true}` when this session has not entered the PIN (unlocked keys are per session id, memory only, so a restart locks everyone)
- Sign-up, sign-in and `/api/session/unlock` call `unlock.activate()`; responses carry `recoveryCode` only when one was just created. Recovery codes and PINs share the lockout via `users.check_with_lockout()`
- `POST /api/session/recover` calls `unlock.end_all_sessions()` before signing the recovering browser in: every other session of the profile is deleted and its keys forgotten
- `DELETE /api/users/me/history` and `POST /api/privacy/consent` go through `history_gate()` (unlocked session), since private mode and a shorter retention delete history
- Export unwraps keys from the PIN, so it works while locked. Losing both the PIN and the recovery code loses the history; there is no admin reset

## Encrypted secrets

**Encrypted secrets** (`vault.py`, `users.py`):
- `users.indmoney` and `oauth_sessions.data` are stored as `enc:v1:<Fernet token>` via `_encode_secret()` / `_decode_secret()`; an empty dict stays a plain `{}`, so SQL can test "connected" with `indmoney <> '{}'` (never `json_extract` on these columns)
- `main.py` runs `vault.check_key()` and `users.encrypt_stored_secrets()` at startup: plaintext rows are encrypted, rows under another key are counted, logged as `stored_secrets_unreadable` and left untouched (they read as `{}`, so the profile shows as disconnected)
- The key lives outside `.data/`; Docker mounts `~/.config/ca-mode` so both run modes share it. Tests set a generated `APP_MASTER_KEY` in `conftest.py` and must never touch the real key file

## Consent and storage modes

**Consent and storage modes** (`privacy.py`, `chats.py`):
- A profile must accept the current `POLICY_VERSION` before `POST /api/chats`, `POST /api/chat`, `POST`/`PUT` on goals and decisions, `GET /api/tools`, `POST /api/snapshots/refresh` or `/auth/indmoney/connect`; otherwise `403 {"consentRequired": true}` (connect redirects home). Reading, deleting and exporting existing data stays allowed
- Every acceptance or settings change appends a `consents` row (version, mode, retention, time); the latest row decides `has_current_consent()`
- Bump `POLICY_VERSION` whenever `NOTICE` changes what is stored or shared: every profile is asked again and its scheduled snapshots pause until it accepts
- `storage_mode` is `device` or `private`. Private keeps chats in `chats._private_chats` (lost on sign-out, mode switch or restart), takes no snapshots, and switching to it deletes saved chats and snapshots. INDmoney tokens are still stored in both modes
- `snapshot_retention_days` (30/90/180/365) is capped by `SNAPSHOT_RETENTION_DAYS`; pruning runs on each capture and when the choice changes
- Export (`POST /api/users/me/export`) needs the PIN and omits the PIN hash and tokens

## Routes and helpers

- Unlock routes: `POST /api/session/unlock`, `POST /api/session/recover`, `POST /api/users/me/recovery-code`; helper `history_gate()`
- Privacy routes: `GET /api/privacy`, `POST /api/privacy/consent`, `POST /api/users/me/export`, `DELETE /api/users/me/history`
- Helpers `consent_required()` and `pin_error()` build the 403 and PIN-failure responses
- Profile routes: `GET /api/session` (current user, `consentRequired`, `storageMode`, `usage`, `backupsInApp`, profile list), `POST /api/users` (create + sign in), `POST /api/session/login`, `POST /api/session/logout`, `GET`/`PUT /api/profile`, `DELETE /api/users/me`

- Admin routes (`main.current_admin()` raises 404 when admin is off, `admin_required()` 401): `GET /admin`, `GET /auth/admin/start` (the shared Google callback hands an admin sign-in to `finish_admin_sign_in()` and redirects to `/admin` or `/admin?error=`), `GET /api/admin/session`, `POST /api/admin/sign-out`, `GET /api/admin/overview`, `PUT /api/admin/profiles/{id}/plan`, `POST /api/admin/profiles/{id}/clear-lockout`, `POST /api/admin/profiles/{id}/sign-out`, `DELETE /api/admin/profiles/{id}` (`{confirmName}`; shares `remove_profile()` with `DELETE /api/users/me`), `POST /api/admin/backups`. Each action logs `admin_*` with the admin's email
- Usage limits: `main.rate_limited(request, group, profile_id)` (429 `{error, rateLimited, retryAfterSeconds}` + `Retry-After`) on `POST /api/chat`, `POST /api/users`, `/api/session/login`, `/unlock`, `/recover` and `POST /api/investigations`; `POST /api/chat` reserves a daily slot before `run_agent` (Free plan only) and releases it unless an answer is returned (429 `{error, dailyLimitReached, limit, resetsAt, retryAfterSeconds, pricingUrl}`, shown by `app.js` as a plain assistant message with a link to the plans; a counted answer carries `X-Questions-Remaining`, shown in the profile dialog's plan row); `POST /api/users` checks Turnstile after the name and PIN pass (`400`/`503` `{turnstileFailed: true}`); `GET /api/session` adds `turnstileSiteKey` only when Turnstile is on, and `app.js` then renders the widget in `#create-turnstile`
- Page views: `POST /api/page-views` (`{route}`; `200 {counted}`, `false` without consent, in private mode or when disabled; `422` for an unknown page)

- `ProfileFields.taxSlabPct` (0/5/10/15/20/25/30 as a number, optional, sealed; read only by `mf_tax`, not in `context.PREFERENCE_LABELS`, so never in the prompt; a `data-number` select in the profile dialog)
- `profile_fields(user, keys)` (without `PROFILE_META_KEYS`), `stored_profile()`, `profile_updated_at()`, `update_profile(user_id, fields, keys)`: profile fields are sealed and stamped with `updatedAt`; they reach the prompts through `context.retrieve_context()`

- `user_access_token()`: None means no usable connection (nothing stored, or the refresh refused with a 4xx); `IndmoneyUnavailable` (a `RuntimeError`) means INDmoney could not be asked (transport error, 5xx, 429), and routes answer `main.indmoney_unavailable()` (503 `{indmoneyUnavailable}`, `Retry-After`) instead of a reconnect prompt; `/api/session` keeps `connected: true`. Refreshes are serialised per profile (`_refresh_locks`), the stored tokens re-read under the lock (a refresh another request finished is reused, also for `force_refresh`), and the new tokens saved at once unless INDmoney was disconnected meanwhile
