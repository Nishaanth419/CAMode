# Mutual funds, returns and tax

Moved out of the always-loaded CLAUDE.md. Read this when changing CAS parsing, the fund ledger, XIRR/benchmarks, capital gains tax, AMFI data, or the INDmoney fund figures.

## Modules

- **`app/cas.py`**: CAS uploads. `parse_statement()` runs `casparser.read_cas_pdf` in memory (offline) on NSDL/CDSL (demat accounts by broker, MF folios, NPS) or CAMS/KFintech (MF folios) statements and keeps only holdings rows in INDmoney's `networth_holdings` layout, so `statement_metrics()` reuses `portfolio_math.compute_metrics()`. Never stored: the PDF, password, investor name, PAN, address, contact details, DP/client IDs. Statements are sealed in `cas_statements` (newest 12 kept). `parse_statement(..., folio_key=)` adds a `ledger` (`mf_ledger.extract`) for detailed CAMS/KFintech statements; `POST /api/cas` passes the profile's folio key and answers `ledger: {available, hint}`
- **`app/mf_ledger.py`**: The mutual fund transaction ledger: `extract()` (per scheme ISIN, AMFI code, names, RTA, opening/closing units, the statement's valuation, transactions' date/type/amount/units/NAV; never descriptions, balances, names, PAN, nominees, advisor), `folioKey` = HMAC-SHA256 of the folio number (whitespace removed) under `folio_salt()` (random, sealed in `users.folio_salt`, never exported; created in `BEGIN IMMEDIATE`), `build()` (newest statement period wins per `(folioKey, isin | amfi:<code> | name:<name>)`; status `unsupported` (gift/segregation/misc/unknown moving units), `unreconciled` (units off by more than 0.001), `incomplete_history` (opening units), else `ok`, each with a `reason`), `ledger_for()`, `has_ledger()` (False when locked), `HINT`
- **`app/mf_math.py`**: Pure `Decimal` lots and returns: `fifo(transactions, *, carried=)` (lots and disposals tagged with `buy_type` / `sell_type` and a merged lot's `Origin`; `carried` lots replace a `SWITCH_IN_MERGER` lot, units shared in proportion; stamp duty split by amount into that date's lot costs, STT shared across that date's disposals, dividend payout is cash and reinvest a lot without cash, a negative `REVERSAL` cancels the newest equal lot, overselling is a `problem`), `xirr()` (Newton from 10%, bisection on [-99.99%, 1000%], `None` with `no_flows` / `no_sign_change` / `no_convergence`), `absolute_return_pct()`, `nav_on_or_before()` and `replay()` (the user's flows summed per date buy and sell benchmark units at that date's NAV, or the previous one up to `MAX_NAV_GAP_DAYS` 5 back, else `unavailable` with the date, or the history start; valued on the fund's own valuation date; a sale larger than the position is `not_comparable`, units never negative; `difference` = the user's value minus the benchmark's)
- **`app/amfi.py`**: AMFI's public `NAVAll.txt` (`AMFI_NAV_URL`): `parse_nav_file()` (category from the section headings, both ISIN columns, `N.A.` skipped; NAV and date are the last two columns, since 2026 the file has Plan and Option columns, joined to the name), `_download()` (follows AMFI's redirect to `portal.amfiindia.com`, never off https `*.amfiindia.com`), plain `amfi_navs` table (`store_navs()`, `navs_for()`), `refresh_if_due(now)` from `snapshots.run_scheduler` (once per local date, a failed try waits an hour, in memory; off unless `MF_DATA_ENABLED`; generic user agent)
- **`app/benchmarks.py`**: Return benchmarks: `BENCHMARKS` (`nifty50` UTI Nifty 50 Index 120716, `nifty500` / `midcap150` / `smallcap250` Motilal Oswal index funds 147625 / 147622 / 147623 (history from 2019-09-11), `liquid` SBI Liquid 119800; direct growth, codes and ISINs checked against the live AMFI file on 2026-11-13), `DEFAULT_BENCHMARK`, `INDEX_NOTE`, `benchmark_for(amfi_category, scheme_name)` (`CATEGORY_BENCHMARK` on the normalised sub-category (`sub_category()`, also used by `mf_tax`), both AMFI spellings; index funds by the index in their name, variants such as Next 50 / Equal Weight / Momentum get none; every none has a reason), plain `benchmark_navs` table (`store_navs()`, `nav_history()`, `latest_nav_date()`), `parse_mfapi()`, `seed_if_needed()` (full history from `MFAPI_URL` `/mf/<code>` when a benchmark has none or its latest NAV is over `RESEED_AFTER_DAYS` 4 days old, so AMFI outages never leave a gap wider than replay's 5 days; a benchmark is downloaded at most once a day (`SEED_AGAIN_SECONDS`), a failed one again after an hour, in memory), `append_from_amfi()` (today's row from `amfi_navs` by ISIN, seeded benchmarks only), `refresh(now)` from `snapshots.run_scheduler` (off unless `MF_DATA_ENABLED`; only the five fixed scheme codes are requested)
- **`app/mf_returns.py`**: Figures for `GET /api/returns`, the page and the tool: `nav_for()` (AMFI or the newer statement NAV, shared with `mf_tax`), `scheme_returns()` (AMFI NAV unless the statement's is newer; `nav_stale` past `fund_data.stale_days()`; lots not matching the closing units make it `unreconciled`; a scheme with no units is worth exactly 0 and needs no NAV, one with units and no NAV is `no_nav` and makes `coverage.pct` null (`valueUnknown` counts them); current value for every scheme, invested/gains/returns only for `ok` and `nav_stale`; XIRR or, under 365 days, `absoluteReturnPct` with `returnReason: under_one_year`), `returns_from()` (portfolio over pooled flows, so switches net out; `coverage` with excluded schemes and reasons), `returns_for()`; `benchmark` per scheme (its category's default, or `none` / `excluded` with a reason) and on `portfolio` (the chosen id, default `nifty50`): `{id, label, status, reason, xirr, absoluteReturnPct, returnReason, value, differenceInr, navDate}` via `mf_math.replay()`, `unavailable` when the history is not downloaded; top-level `benchmark` (`schemeName`, `schemeCode`, `navDate`, `note`, `options`)
- **`app/mf_tax.py`**: Capital gains tax on mutual fund units, pure `Decimal` (docs/superpowers/plans/2026-11-13-mf-returns-batch-3.md has the verified rule table and what could not be confirmed): `MF_TAX_RULES` (dated `TaxRule` rows: tax classes, sale and purchase dates, `long_term_after_months` (None: always short-term), `st_rate` (`"slab"`) / `lt_rate`, `lt_exemption_inr`, `indexation`, `sections` in the act in force on the sale date (1961: 111A/112A/50AA/112; from 1 Apr 2026: 196/198/76/197), `act`, `source` citation; every `Gain` carries its `rule_id`), `rule_for()`, `is_long_term()` / `long_term_on()` (more than N months: the day after the N-month anniversary), `COST_INFLATION_INDEX` / `indexed_cost()`, financial years (`fy_of()`, `parse_fy()` 422 messages, `fy_options()`, `MIN_FY` 2023-24, `exemption_for()`: Rs 1,00,000 for FY 2023-24, Rs 1,25,000 after, per year in aggregate), `tax_class()` (`equity` / `debt` (specified fund) / `other` (gold, international, FoFs: specified under the old 35% definition until FY 2024-25) / `unclassified`, from the AMFI category via `benchmarks.sub_category()`; balanced advantage, multi-asset, domestic FoF, solution-oriented and unknown categories are equity only when a redemption paid STT), `tax_lots()` (`SchemeLots`: only ledger-`ok` schemes whose lots match the closing units have gains; mergers carried over when exactly one scheme merged out and one in that day in the folio, else flagged (`FLAG_MESSAGES`); 31 Jan 2018 grandfathering via `nav_2018()` (`casparser` offline `nav_search`, the merged lot's `Origin` ISIN and ratio), else `no_2018_nav`; indexation only on `non_equity_indexed`), `position(lots, fy, slab_pct)` (rows per rule and term, `totals`, `setOff` (short-term losses against slab-taxed, then other short-term, then non-equity and equity long-term gains; long-term losses only against long-term), `exemption` used/left (highest rate absorbed first), `tax` (`estimated` / `partial` / `none` with `missing` (`slab`, `funds`: unclassified gains or a left-out fund that sold this year): slab-taxed gains taxed only with `taxSlabPct`, never shown as 0; 4% cess, no surcharge or rebate), `excluded` with `soldThisYear`, `carryForward`, `unclassified`, `schemes`, `excluded`, notes), `planning(lots, navs, today, position, slab_pct)` (current FY only, FIFO: `gainHarvest` within the exemption left stopping before the first short-term or locked lot (`stoppedBy`), `lossHarvest` (largest-loss FIFO prefix, `couldOffset`), `turningLongTerm` within 90 days with `taxNow` / `taxAfter` / `extraTax` (only lots where waiting lowers the tax), `elssLocked` (36 months), `left` (no NAV); exit-load and 25 March notes; no buy/sell wording), `tax_from()` / `tax_for()` (`GET /api/tax`, the tool)

- **`app/fund_data.py`**: INDmoney mutual fund figures for a goal's suitable categories: `INDMONEY_CATEGORIES` (slug → `CATEGORIES` id), `parse_category()` / `parse_scheme()` / `parse_benchmarks()` (`Decimal`, each metric `{value, asOf, status, source}`, `missing` with reasons), `fetch_categories()` (live MCP, in-memory cache), `build_comparison()`, `goal_comparison()`, `tool_payload()` and `fund_comparison_tool()` (`get_goal_fund_comparison`).

## Fund figures

**Fund figures** (`fund_data.py`, layout in `tests/fixtures/indmoney_funds.py`, recorded with `scripts/inspect_indmoney_shapes.py --funds --labels`):
- `get_mf_by_category` rows: `id`, `name`, `category` ("flexi cap", the slug with spaces), `risk` ("Very High Risk"), `expense_ratio`, `return_1yr/3yr/5yr`, `nav_date` ("15 Oct 2026"), `launch_date` (often ""), plus INDmoney's `rating` / `ind_ranking` (always dropped). `get_mf_funds_details` (`data[].fund_id`, `data[].data.fund_detail`) has `benchmark_name` and no date anywhere, so only the benchmark is taken from it
- Returns are dated by `nav_date`; status `current` only when dated and within `FUND_STALE_DAYS` (5), else `stale`; no readable or a future date is `undated`. Expense ratio, risk and benchmark are always `undated` with `retrievedAt`. The frontend (`finance.js` `fundMetricNote()`) never shows an undated figure as current
- Missing is never zero: a return of exactly 0 (INDmoney's "no figure"), a period longer than the scheme has existed (`launch_date`), a return outside (-100, 1000], an expense ratio outside 0.01–3 are `missing` with the reason
- Only slugs in `INDMONEY_CATEGORIES` are fetched; a row is kept only when its own `category` maps to the category asked for, else it is `excluded` with the reason. Listing call: `sort_key: "aum"`, descending, `FUNDS_PER_CATEGORY` (5); results sorted by name. Unsuitable categories are never fetched (`unsuitableCategories` lists them)
- Nothing is stored (no POLICY_VERSION change): `_cache` keyed by (profile, category) for `CACHE_SECONDS` (6 h), cleared on INDmoney disconnect; failed listings are not cached
- `GET /api/goals/{id}/funds?category=` (consent + unlocked; 422 for an unknown or unsuitable category). `get_goal_fund_comparison` goes to Portfolio Analyzer only, for profiles with a goal; the prompt then gets `agent.FUND_COMPARISON_RULES` instead of `NO_FUND_DATA_RULE` (Finance Agent always gets the latter). Quoted figures pass `_number_warning` because they are in the tool result
- Goals page: "Show fund figures" inside each goal card's Fund figures disclosure (`fundBlock()` / `fundComparisonHtml()` in `pages.js`), every figure with its date and source beside it

## Routes

- CAS routes: `GET /api/cas`, `POST /api/cas` (JSON `{password, pdfBase64}`; needs an unlocked session, consent, and `device` mode; answers `ledger: {available, hint}`), `DELETE /api/cas/{id}`
- Tax route: `GET /api/tax?fy=` (profile + unlocked, no consent; default the current FY in `SNAPSHOT_TIMEZONE`; 422 `{error, fys}` for a malformed, future or pre-2023-24 year; `mf_tax.tax_for()` with the profile's `taxSlabPct`: `{available, fy, fys, current, position, planning (current year only), navDate, statementPeriod}` or `{available: false, hint}`)
- Returns route: `GET /api/returns` (profile + unlocked, no consent; `mf_returns.returns_for()`: `{available, schemes, portfolio, coverage, navDate, statementPeriod}` or `{available: false, hint}`)
