# Frontend

Moved out of the always-loaded CLAUDE.md. Read this when changing anything under `frontend/` (pages, rail, charts, service worker, icons). The rules that apply while editing are in [../../frontend/CLAUDE.md](../../frontend/CLAUDE.md).

## Public pages (backend)

- **`app/public_pages.py`**: Pages served without a profile: `app_shell(origin)` (index.html with `{{origin}}` replaced, escaped, for absolute `og:*` URLs; file read once), `privacy_page()` (renders `privacy.NOTICE`, dated from `POLICY_VERSION`), `terms_page()` (fixed plain terms dated `TERMS_UPDATED`: not advice, read-only connections, fair use, links to pricing and privacy; the contact is `PRICING_CONTACT_EMAIL` when set, escaped), `pricing_page()` (renders `plans.PLANS`; buttons are `mailto:` the contact, else a note), `not_found_page()`, `admin_page()` (noindex, filled by `js/admin.js` + `css/admin.css`), `robots_txt()` (disallows `/api/`, `/auth/`, `/admin`), `sitemap_xml()` (only `INDEXABLE_PATHS` = `/privacy`, `/terms`, `/pricing`; the app shell is `noindex` because the sign-in screen lists profile names). `main.http_error()` serves the HTML 404 for unknown GET/HEAD pages and leaves `/api/` and `/auth/` on FastAPI's JSON errors

- Public pages: `GET /` and `/index.html` (app shell via `public_pages.app_shell()`), `GET /privacy`, `GET /terms`, `GET /pricing`, `GET /robots.txt`, `GET /sitemap.xml`

## Frontend

### Frontend
- Static HTML/CSS/JS in `frontend/` (installable PWA)
- `index.html`: app shell (sidebar nav in groups Overview / Assistant / Plan / Explore, Recent chats with the New chat `+`, profile footer; top bar with the conversation search (Cmd/Ctrl+K), status pill, theme toggle and, below 900px, the brand and a profile avatar; `#tabbar` below 900px: Home, Holdings, Ask, Goals and More, which opens the sidebar as a drawer), profile picker (`#profile-gate`: the picker, `#google-sign-in`, create and `#profile-claim-form`, unlock, recovery, and the `#consent-form` privacy step), profile dialog (`<dialog id="profile-dialog">`: Brokers, Plan and About you as `.dialog-section`s with `.dialog-section-title` headings, then the `#data-zone` privacy settings and the delete `.danger-zone` as folding sections). The sign-in card and dialogs use 44px (gate) and 40px (dialogs) controls; destructive actions (`#clear-history`, `#delete-profile`, `#goal-delete`, `.danger-text`) are `.danger-button`, the outlined "Delete" style from the System board (`--danger-border`). An open `<details>` is laid out through `::details-content` in current Chrome, so its grid and gap are set there too
- `app.js`: profile sign-in/creation (`authMode` from `/api/session`: the picker, or `showAccountGate()` for Google sign-in, create and claim), privacy notice and storage choices, export and history clearing, profile dialog (including INDmoney connect/disconnect), chat UI (`#chat-head`: the chat title, agent and last message day (chats store no start date), Delete chat and New chat; below 900px Back to the page Ask AI was opened from and icon-only actions, and the top bar hides; a centred column about 780px wide: questions as right-aligned bubbles, answers with a meta line from `answerMeta(trace)` (agent · model from the trace, else the picker · snapshot date when the trace shows one), a 16px lead paragraph and tables scrolling in their box; follow-up `data-prompt` chips under the latest real answer only (`addMessage(..., { answer: true })`, `placeFollowUps()`); one composer box (`.composer` grid: textarea, Finance Agent / Portfolio Analyzer `.seg`, the model as a short "<model> ▾" label with the native `#provider-picker` laid over it, "Enter to send", round Send; below 900px the switch and model sit above the box, which stays above the tab bar; while the on-screen keyboard is open `visualViewport` sets `--viewport-h` and `body.keyboard-open` hides the tab bar); `setLatestAnswer()` fires `ca:answer` with the latest answer's trace for the rail), sidebar recent chats (newest 6), `refreshSnapshot()`, Markdown rendering (links limited to http(s)/mailto), Plotly charts, theme toggle. Fires `ca:session`, `ca:chats` and `ca:snapshot` document events for the pages
- `ui.js` (loaded after `trace.js`, before `app.js`, exported for Node tests in `tests/js/ui.test.js`): pure chat and dialog helpers: `isComposingEnter()` (Enter mid-IME never sends), `plainError(status, body)` (CA Mode's own `error` sentence, else a plain one per status; a proxy page never reaches the user) and `errorText(error)` (only plain `Error`s pass; a failed fetch reads as a connection problem), `lostChatResponse()` / `savedAnswerFor()` (a dropped connection or a proxy's timeout page on `POST /api/chat`: `app.js` `waitForSavedAnswer()` re-reads `GET /api/chats/{id}` every 10 s for up to 150 s and shows the answer the server saved after the send), `extractChartBlocks()` / `parseChartSpec()` (only fenced chart blocks, same pattern as `charts._CHART_BLOCK`; bold or inline chart JSON stays text) and `withPending(button, statusEl, action)` (every profile dialog action: button disabled and `aria-busy` while it runs, a second click ignored, a failure shown in the dialog's status line; delete has its own `#delete-status`)
- `trace.js` (loaded after `finance.js`): answer trace timeline, investigation evidence card and Activity helpers (see "Answer trace and Activity")
- `finance.js` (loaded first): pure helpers shared by the pages and the rail and exported for Node tests: Indian money formatting, SIP/lumpsum/goal math, `goalKind()`, `historyChange()`, `portfolioInsights()` (observations about the user's own holdings, never market news) and goal formatting (`amount()`, `amountShort()`, `totalsByCurrency()`, `goalStatus()`, `baseScenario()`, `goalVerdict()` (the card's one sentence from the plan), `gapOption()` / `gapOptions()` (the "Ways to close the gap" tiles); plans come from the server) and `incomeTax()` with `TAX_RULES` (FY 2026-27 slabs, 87A rebate and marginal relief, surcharge with marginal relief, 4% cess). Update `TAX_RULES`, its label and `tests/js/finance.test.js` after each budget
- `rail.js` (loaded last): the right rail on Ask AI: "This answer used" (the latest answer's sources from `trace.js` `answerSources()`: saved snapshot and its date, each tool with its name and whether it was saved data or a live INDmoney call, saved details, the number check, steps not kept; updated on `ca:answer`), "Your portfolio" (net worth from the latest snapshot, change over the saved history with `spanPhrase()`, broker attention line, Open holdings) and Recent chats (newest 4 other than the open one; updated on `ca:chats`); shown only on Ask AI (`body.route-chat`, wider than 1280px; elsewhere pages use the full width up to `--content-w` 1180px), so it loads the portfolio only there: `ca:session`, `ca:snapshot` and `ca:brokers` mark it stale off Ask AI and `ca:route` (fired by `pages.js` `renderRoute()`) renders it on arrival; clears on `ca:session-ended`
- Session events: `loadChats()` sets `isSessionReady = false` and fires `ca:session-ended` (pages and rail drop the previous profile's figures), then `ca:session` once the profile is signed in, unlocked and consenting. Data loaders in `pages.js` (`getPortfolio()`, `getHistory(days)`, `getGoals()`) share one cached request; a 401/403 from them triggers a single `reloadSession()`
- `pages.js` (loaded after `app.js`, uses its globals): hash routes `#/` (Home), `#/chat` (Ask AI), `#/activity` and `#/activity/<id>` (saved investigations), `#/portfolio`, `#/holdings` and `#/holdings/<source>` (see Holdings below; `ROUTE_ALIASES` sends the old `#/investments` there with `history.replaceState`, so page views count `holdings`), `#/returns` (Returns & tax: `renderReturns()`, portfolio and per-fund returns from `GET /api/returns`, status chips, NAV date and source, a "Compared with a benchmark" card with `.filter-chip`s (`data-returns-benchmark`, `?benchmark=`) and a "vs benchmark" column; `finance.js` `returnFigure()`, `returnStatus()`, `navNote()`, `benchmarkFigure()`, `benchmarkDifference()`, `benchmarkNavNote()`; a Returns / Tax tab bar (`returnsTabs()`, `data-returns-tab`); `#/returns/tax` (`renderTax()`: `GET /api/tax?fy=`, financial-year `.filter-chip`s (`data-tax-fy`), KPI strip (realised short- and long-term, exemption left, estimated tax), the exemption meter, "Gains by rule" `.card-table`, losses and carry-forward, funds not in the estimate, for the current year the planning cards (`.planning-list`) and their notes, an "Add your tax slab" button (`data-open-profile`; saving the profile fires `ca:profile` and the tab re-renders); `finance.js` `fyLabel()`, `taxClassLabel()`, `termLabel()`, `taxRate()`, `exemptionShare()`, `taxEstimate()`, `TAX_SLAB_NOTE`); its empty state links to the CAS card on `#/holdings`), `#/planning/<sip|lumpsum|goal|emi|tax>` (calculators run in the browser), `#/markets` (`#/markets/funds` focuses the fund form), `#/goals`, `#/reports`, `#/chats`; `navigate(route)` switches between the chat view and `#page-view`. Prompt buttons anywhere use `data-prompt` / `data-agent` (one delegated listener in `app.js`)
- Home (`#/`, `renderHome()`): page header (greeting, "Your money at a glance", Refresh snapshot and New chat), a hero row (net-worth card: exact figure, change pill from `historyChange()` with `spanPhrase()`, 1M/3M/6M/1Y `#home-range`, area chart; "Ask about your money": a textarea composer (Enter sends through `runPrompt()` with the current agent, Shift+Enter is a new line) and four `data-prompt` rows), a `.kpi-strip` of 4 `kpiCard()`s (Invested and Returns over holdings with a cost, Today's change from `dayChange()`, Liabilities), then "Where it is invested" (`allocationShares()`: stacked bar plus a list with full names, values and shares, `.series-1`…`.series-8` colours), "Largest holdings" (names wrap; value plus P&L, or "No cost reported"), Goals (progress bars, pill tone from `goalTone()`), "What changed today" (`portfolioInsights()`, each with an "Ask why" prompt) and "Continue a chat". Disconnected, private and no-snapshot states show one empty-state action in the hero and hide the KPI strip and period picker. Layout uses container queries on `.page-dashboard` and `#portfolio-body` (`container-type: inline-size`): below 860px the hero splits and the order is net worth, KPIs, then the composer; KPIs go 2 across below 720px
- Portfolio (`#/portfolio`): the same header pattern; five `kpiCard()`s in `.kpi-strip-5` (5 across, else 2 across with Net worth spanning the first row, so Liabilities never sits alone)
- Holdings (`#/holdings`, `renderHoldings()`; Investments was merged into it): header actions Download CSV (`#holdings-csv`: every row of the selected source, whatever the filters show) and Connect a broker; reconnect banners; underline source tabs from `holdingsTabs()` (`All holdings`, INDmoney, then each broker, with logos, row counts and a Stale pill; `#/holdings/<id>`; a broker tab adds "Refresh from <broker>"), all from `GET /api/holdings/combined`; then a `.kpi-strip` (Current value, Invested and Gain over holdings with a cost, Today's change), asset-type filter chips, search and sort (`finance.js` `holdingTypeCounts()` / `filterHoldings()`: missing figures sort last), the `.holdings-table` (tile from `holdingInitials()`, Value with USD under it, Invested, Gain or "No cost reported", Share bar, 1 day, Ask; missing values are "—"), the source's `data_notes`, a "By broker" split (`figures.by_broker`) and the `#cas-card` CAS statements card (upload, the detailed-CAS hint linking to `#/returns`, saved statements as a list, Ask). `#holdings-body` is a container: between 640px and 900px the share bar hides, below 640px the table rows become cards (`grid-template-areas`). With no source at all: the private-mode notice, "No snapshot yet" (INDmoney connected) or Connect a broker
- Goals (`#/goals`, `renderGoals()`): header with "Add a goal" (`#add-goal`, hidden at `MAX_GOALS`), a `.kpi-strip` (`goalStats()`: On track n of m with drafts not counted, Total targets, Saved so far, Saving each month; `totalKpi()` shows the first currency and the others in the note, never summed), the underfunded callout, then one full-width `goalCard()` per goal: `goalRing()` (SVG ring of `plan.progressPct`, "—" when unknown, never 0%), name and `.tone-pill` (`goalStatus()` wording, "Draft" for drafts), "<target> by <date>", `goalVerdict()`, `goalFigures()` (Saved and linked = `startingAmount`, Each month, Assumed return or "None"), the plan's warnings (`.goal-checks`), `gapPanel()` only for a `shortfall` / `no_time_left` feasibility (up to 3 tiles on the first basis, every other alternative under "Other ways"), and a footer of disclosures (`[data-goal-panel]`, one open per card: Scenarios (feasibility, table, the no-growth alternatives of a goal on track only if returns hold, assumptions, saved time), Suitable investment types, Fund figures, Assigned holdings, Still to answer) plus Edit, Delete and "Ask about this goal". Below the cards: "Your investments and goals" (`.alloc-table`, rows become cards below 640px) and "What the assistant can use". `#goals-body` is a container; below 900px the KPIs go 2 across, the ring stacks above the text and the footer buttons are 44px with the actions on their own row
- Calculators (`#/planning/<id>`, `renderPlanning()` / `renderCalcOutput()`): page header, `#calc-tabs` as a segmented control (scrolls sideways on phones), inputs card left (number box plus slider per field) and results right (`.kpi-strip-3` of `kpiCard()`s, the "Year by year" chart as a page line chart with `xTitle: 'Year'`, the tax table, note and actions); `#calc-body` is a container and stacks below 900px. `CALCULATORS` and `TAX_RULES` hold the maths
- Markets (`#/markets`, `renderMarkets()`): KPI strip (Day change, Holdings up, Holdings down, Unchanged), Top gainers / Top losers (`moverTable()`), the market-cap donut, then the stock chart and fund comparison forms as cards and Live questions as `.prompt-rows`. Reports (`#/reports`): `.kpi-strip-3`, net worth chart, Change by period and Month-end tables, Downloads; Returns uses `.kpi-strip-5` and the same cards. All chats (`#/chats`): one `.chat-group-card` per period with Home's chat rows; its empty states offer Ask a question or Clear search (`data-clear-chat-search`)
- Tables over three columns become cards below 640px: `.card-table` (Markets movers, Reports, Returns by fund) turns each row into a card, the first cell as its title and every other cell a `data-label` line; the page body must be a container (`#calc-body`, `#markets-body`, `#reports-body`, `#returns-body`, `#activity-body`, `#all-chats` are, with `grid-template-columns: minmax(0, 1fr)`)
- Empty states (`notice()` → `.panel.empty-panel`, Home's `.home-empty`, the 404 card) are dashed boxes that say why, then offer one action
- History charts (Home hero, Portfolio trend, Reports net worth) go through `pages.js` `historyChartHtml()` → `renderDataChart(spec, { history: true, compact, area, height })`: `app.js` `historyLayout()` / `historyTraces()` / `plotlyConfig()` draw them with no range slider, mode bar or zoom, y ticks from `finance.js` `niceTicks()` labelled with `moneyShort()`, axis titles (left out when `compact`), hover with `money()` (Indian grouping), and transparent backgrounds. Calculator charts use the same path with `xTitle` / `yTitle` (years as category labels), and page donuts (Portfolio allocation, Markets market cap) pass `{ page: true }`: no toolbar or zoom, ₹ in Indian format on hover. Answer charts in chat keep the toolbar and range slider. The Bars/Donut/Data buttons under a chart use `data-set-chart-view` and one delegated listener (the Content-Security-Policy blocks inline handlers)
- `sw.js`: service worker that serves the cached app shell offline (API data is always fetched live): navigations fall back to the cached `/`, shell assets (`APP_SHELL`) are fetched network-first and kept by path, and offline lookups ignore the `?v=` query (`tests/js/sw.test.js` runs it in a fake worker scope)
- `pages.js` `countPageView()` POSTs `/api/page-views` once per route change after sign-in (skipped in private mode, never retried); `ROUTE_META` sets `document.title` and the meta description per hash route; an unknown hash shows the `not-found` page section instead of falling back to Home
- Icons: `icon.svg` (source), `favicon.ico`, `apple-touch-icon.png`, `icon-192/512.png`, `icon-maskable-512.png` and `og-image.jpg` are generated by `python -m scripts.build_icons` (macOS `sips`) from `frontend/icon.svg` and `assets/brand/*.svg`; commit the outputs
- `css/public.css` styles `/privacy` and the 404 page (system light/dark, no app shell)
- Plotly is loaded from the CDN by a `<script>` tag in `index.html`
- Bump the `?v=` cache-busters in `index.html` and `CACHE_NAME` in `sw.js` when changing frontend assets
