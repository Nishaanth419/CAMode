- [OWASP GenAI LLM Top 10 — repository README](https://raw.githubusercontent.com/GenAI-Security-Project/GenAI-LLM-Top10/main/README.md) — authoritative enumeration and ordering of the 2026 edition, used in preference to secondary coverage that disagreed with it.
- [LLM00:2026 Preface](https://raw.githubusercontent.com/GenAI-Security-Project/GenAI-LLM-Top10/main/2026/final/LLM00_Preface.md) — the governing thesis (build the system so that when the model is fooled, nothing important breaks) and the LLM-vs-agentic scope boundary.
- [LLM01:2026 Prompt Injection](https://raw.githubusercontent.com/GenAI-Security-Project/GenAI-LLM-Top10/main/2026/final/LLM01_PromptInjection.md) — no reliable prevention; the static-vs-adaptive attack-success gap; provenance-labelled data channel; invisible-Unicode ranges; memory writes as privileged operations; Rule of Two; adaptive red-teaming.
- [LLM02:2026 Sensitive Information Disclosure](https://raw.githubusercontent.com/GenAI-Security-Project/GenAI-LLM-Top10/main/2026/final/LLM02_SensitiveInformationDisclosure.md) — non-obvious disclosure surfaces, layered redaction, per-user query budgets, gating logprobs, the observability-platform leak pattern.
- [LLM03:2026 Excessive Agency](https://raw.githubusercontent.com/GenAI-Security-Project/GenAI-LLM-Top10/main/2026/final/LLM03_ExcessiveAgency.md) — minimize tools, functionality, and permissions; execute in the user's context across chained calls; complete mediation with a graduated policy; rate limiting with circuit breakers.
- [LLM04:2026 Supply Chain](https://raw.githubusercontent.com/GenAI-Security-Project/GenAI-LLM-Top10/main/2026/final/LLM04_SupplyChain.md) — AI/ML BOM inventory, model signing with a transparency log, "signing proves integrity and origin, not safety", verifying AI-suggested dependencies.
- [LLM05:2026 Data and Model Poisoning](https://raw.githubusercontent.com/GenAI-Security-Project/GenAI-LLM-Top10/main/2026/final/LLM05_DataModelPoisoning.md) — RAG trust boundaries, dataset version control for rollback, gating retraining and feedback loops, inference artifacts as security-relevant code.
- [LLM06:2026 Unbounded Consumption](https://raw.githubusercontent.com/GenAI-Security-Project/GenAI-LLM-Top10/main/2026/final/LLM06_UnboundedConsumption.md) — token-based rate limits, pre-flight estimation, hard non-overridable spend caps, agentic circuit breakers, graceful degradation.
- [LLM07:2026 Misinformation](https://raw.githubusercontent.com/GenAI-Security-Project/GenAI-LLM-Top10/main/2026/final/LLM07_Misinformation.md) — claim-check-act separation, validating tool arguments against current state, groundedness over self-reported confidence, mandatory structured fields to surface omissions.
- [LLM08:2026 Hidden Context Exposure](https://raw.githubusercontent.com/GenAI-Security-Project/GenAI-LLM-Top10/main/2026/final/LLM08_HiddenContextExposure.md) — renamed and broadened from the 2025 edition's System Prompt Leakage; assume all model context is user-visible; never rely on hidden context as a control.
- [LLM09:2026 Vector and Embedding Weaknesses](https://raw.githubusercontent.com/GenAI-Security-Project/GenAI-LLM-Top10/main/2026/final/LLM09_VectorAndEmbeddingWeaknesses.md) — tenant scoping inside the index query, chunk-level ACLs, index segregation by trust tier, ingest normalization, embedding deletion and re-embedding, embeddings-as-breach.
- [LLM10:2026 Improper Output Handling](https://raw.githubusercontent.com/GenAI-Security-Project/GenAI-LLM-Top10/main/2026/final/LLM10_ImproperOutputHandling.md) — model-as-untrusted-user, parameterized queries, context-aware encoding, CSP, ANSI/control-character sanitization, disabling Markdown image and link-preview auto-fetch.
- [ASI 2026 framework mapping, in the OWASP LLM Top 10 repo](https://raw.githubusercontent.com/GenAI-Security-Project/GenAI-LLM-Top10/main/2026/final/mappings/asi-2026.json) — the ASI01-ASI10 titles used in section 12, taken from this mapping rather than the ASI publication itself; secondary sources reword several, so prefer these forms.
- [NIST AI 600-1 GenAI risk categories, mapping file in the OWASP repo](https://raw.githubusercontent.com/GenAI-Security-Project/GenAI-LLM-Top10/main/2026/final/mappings/nist-ai-600-1.json) — the 12 GenAI risk category names and the note that NIST assigns them no alphanumeric ids. **Provider API (Anthropic; `anthropic-api.md`)**

- [Prompt caching](https://platform.claude.com/docs/en/build-with-claude/prompt-caching.md) — prefix-hash mechanics and render order, breakpoint limit, per-model minimum cacheable lengths, read/write price multipliers, the invalidation matrix, verification via usage counters. Re-read 2026-09-28. It confirms: the minimum-length table (512 on Fable 5.1, Mythos 5.1, Opus 5.5, Opus 5, Fable 5, and Mythos 5; 1,024 on Opus 4.8, Sonnet 5, and Sonnet 4.6; 2,048 on Opus 4.7; 4,096 on Opus 4.6 and Haiku 4.5); automatic caching through a top-level `cache_control`, which puts the breakpoint on the last cacheable block and takes one of the 4 slots; and mid-conversation system messages on Fable 5/5.1, Mythos 5/5.1, Opus 5.5, Opus 5, and Opus 4.8, but not Sonnet 5. Cache reads are 0.1x everywhere except 0.025x on Fable 5.1 and Mythos 5.1 and 0.05x on Opus 5.5. Since the 2026-09-28 review, `anthropic-api.md` includes Opus 5.5 in the 512-token row, the cache-read exceptions, and the mid-conversation list, and gives the 0.025x rate for Mythos 5.1 as well as Fable 5.1. Its 512-token row still leaves out Mythos 5/5.1, which the page lists.
- [Structured outputs](https://platform.claude.com/docs/en/build-with-claude/structured-outputs.md) — `output_config.format`, strict tool use requirements, the supported and unsupported JSON Schema keyword sets, refusals not being schema-guaranteed, truncation returning partial content. Re-read 2026-09-28. It confirms that the Python and TypeScript SDKs remove unsupported constraints from the schema they send and then validate the response client-side against the original schema, which is SKILL.md section 3's "some SDKs strip them". It also confirms the supported string formats (`date-time`, `time`, `date`, `duration`, `email`, `hostname`, `uri`, `ipv4`, `ipv6`, `uuid`), that `additionalProperties` must be `false` on objects, and the unsupported features: recursive schemas, numerical and string-length constraints, and complex array constraints (only `minItems` of 0 or 1 is allowed).
- [Citations](https://platform.claude.com/docs/en/build-with-claude/citations.md) — all-or-none enablement, the three location types and their indexing conventions, guaranteed-valid parsed pointers versus prompt-based quoting, incompatibility with structured outputs.
- [Prompt engineering overview](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/overview.md) — the prerequisite ordering in section 1, and the point (section 5) that latency and cost are usually better addressed by model choice than prompt wording.
- [Create strong empirical evaluations](https://platform.claude.com/docs/en/test-and-evaluate/develop-tests.md) — distribution matching, the named edge classes, automating grading, volume over hand-grading, using a different model to grade than to generate.
- [Define your success criteria](https://platform.claude.com/docs/en/test-and-evaluate/define-success.md) — SMART criteria, quantifying subjective dimensions, and including latency and price per call among the criteria.
- [Anthropic — Building effective agents](https://www.anthropic.com/engineering/building-effective-agents) — the workflow-versus-agent distinction in section 9, the five named workflow patterns (trimmed from SKILL.md 2026-09-28), plus the agent-computer-interface guidance (section 3).
- [Models overview](https://platform.claude.com/docs/en/about-claude/models/overview.md) — The current lineup's ids and limits: Fable 5.1 (`claude-fable-5-1`), Opus 5.5 (`claude-opus-5-5`), and Sonnet 5 at 1M context and 128K max output, and Haiku 4.5 at 200K and 64K. Fable 5, Opus 5, Opus 4.8, Opus 4.7, Opus 4.6, and Sonnet 4.6 are listed as legacy models that are still available. Default effort is `high`, except `medium` on Opus 5.5; Haiku 4.5 does not support effort. The Models API returns `max_input_tokens`, `max_tokens`, and a `capabilities` object. The page presents Opus 5.5 as a current model and the recommended starting point for most workloads, and the 2026-09-28 review removed the "launching; use only when explicitly requested" label from its row in `anthropic-api.md`. Its pricing note gives cache reads at 10% of base input, 2.5% on Fable 5.1 and Mythos 5.1, and 5% on Opus 5.5. Read 2026-09-28.
- [Claude API errors](https://platform.claude.com/docs/en/api/errors.md) — Error type names, including `401 authentication_error`, `402 billing_error`, and `413 request_too_large`. The official SDKs retry connection errors, rate limits, and 5xx twice by default. It also confirms four 400s: forced `tool_choice` `any`/`tool` on Opus 5.5, Fable 5.1, and Mythos 5.1, token-counting endpoint included; assistant prefill on Claude 4.6 and later; `thinking.type: "enabled"` on Claude 4.7 and later; and `thinking.type: "disabled"` on Fable 5/5.1, Mythos 5/5.1, and Opus 5.5. The page also lists `409 conflict_error` and `504 timeout_error`, which the error list in `anthropic-api.md` leaves out. Read 2026-09-28.
- [Troubleshooting thinking](https://platform.claude.com/docs/en/build-with-claude/thinking-troubleshooting.md) — The per-model thinking table. Thinking is always on for Fable 5/5.1, Mythos 5/5.1, and Opus 5.5; on by default for Opus 5 and Sonnet 5; off by default for Opus 4.8, 4.7, and 4.6 and Sonnet 4.6. `"enabled"` is rejected on Claude 4.7 and later and deprecated on the 4.6 models. Opus 5 accepts `"disabled"` only at effort `high` or below. Haiku 4.5 supports extended thinking only. The page also describes the Opus 5 failure mode with thinking disabled: a tool call written into the text never runs, and `<thinking>` tags can leak. It does not give the `budget_tokens` minimum or the sampling-parameter rules; those rest on the claude-api skill. Read 2026-09-28.
- [Effort](https://platform.claude.com/docs/en/build-with-claude/effort.md) — Effort is set in `output_config.effort`. The default is `high` on every model that supports effort except Opus 5.5, where it is `medium`. `xhigh` is available from Opus 4.7 on, and not on Opus 4.6 or Sonnet 4.6. Haiku 4.5 is not in the supported-models list. Read 2026-09-28.
- [Stop reasons](https://platform.claude.com/docs/en/build-with-claude/handling-stop-reasons.md) — The seven `stop_reason` values, including `model_context_window_exceeded`. `pause_turn` fires when a server-tool loop reaches its default limit of 10 iterations; resume by sending the response back as it is, with no continuation prompt. `stop_details` is `null` for every stop reason except `refusal`. Read 2026-09-28.
- [Refusals and fallback](https://platform.claude.com/docs/en/build-with-claude/refusals-and-fallback.md) — A refusal is a normal HTTP 200 response, and partial output from a mid-stream refusal is to be treated as incomplete and discarded. `fallbacks: "default"` takes the `server-side-fallback-2026-07-01` header. `fallbacks` is not supported on Message Batches (the batch item comes back as an errored result) and is not available on Bedrock, Google Cloud, or Foundry, where the SDK middleware replaces it. The page says server-side fallback is in beta on the Claude API but does not mention Claude Platform on AWS; that availability rests on the claude-api skill alone. The page says to branch on `stop_reason` or `stop_details.type`, not on the inner `stop_details` fields. `stop_details` is always present on a refusal, and its `category` and `explanation` are both `null` when the refusal maps to no named category. `stop_details` is `null` for every other stop reason. The `-2026-07-01` header accepts both the `"default"` form and the explicit-list form (the page's example is `fallbacks: [{"model": "claude-opus-4-8"}]`). `-2026-06-01` accepts only the list form, and any other `server-side-fallback-*` value returns 400. Since the 2026-09-28 review, `anthropic-api.md` matches the page on all of these points. Before that it followed the claude-api skill's older wording. Read 2026-09-28.
- [Mid-conversation system messages](https://platform.claude.com/docs/en/build-with-claude/mid-conversation-system-messages.md) — Supported on Fable 5/5.1, Mythos 5/5.1, Opus 5.5, Opus 5, and Opus 4.8, not on Sonnet 5, with no beta header. A system message that carries content must come right after a `user` turn (or an `assistant` turn ending in a server tool result), must come before an `assistant` turn or end the array, and cannot be `messages[0]`. The 2026-09-28 review added Opus 5.5 to the supported list in `anthropic-api.md`. The page says only that the feature is not available on Sonnet 5. The 400 that `anthropic-api.md` gives for Sonnet 5 rests on the claude-api skill. Read 2026-09-28.
- [Token counting](https://platform.claude.com/docs/en/build-with-claude/token-counting.md) — The `/v1/messages/count_tokens` endpoint. Claude 4.7 and later models, including the Fable and Mythos models, use a newer tokenizer that produces about 30 percent more tokens for the same text than earlier models, so recount prompts against the target model. It names Fable 5.1, Mythos 5.1, Fable 5, and Mythos 5 as sharing the tokenizer introduced with Opus 4.7. That fits the 1-1.35x range in `anthropic-api.md`. The 2026-09-28 review changed that file to name every model on the tokenizer and to limit "migrating from" to Opus 4.6, Sonnet 4.6, Haiku 4.5, or older. Read 2026-09-28.
- [Migrating to Claude Opus 5.5](https://platform.claude.com/docs/en/models/opus-5-5/migration-guide.md) — Opus 4.7 introduced the current tokenizer, and later Opus models, Opus 5.5 among them, use it too. It can produce roughly 1x to 1.35x as many tokens as models before Opus 4.7 (up to about 35% more, depending on content). This is the live source for the 1-1.35x range that `anthropic-api.md` earlier based on the claude-api skill alone. Read 2026-09-28.
- [What's new in Claude Sonnet 5](https://platform.claude.com/docs/en/models/sonnet-5/whats-new-sonnet-5.md) and [Claude Sonnet 5 overview](https://platform.claude.com/docs/en/models/sonnet-5/overview.md) — Sonnet 5 uses a new tokenizer that produces about 30% more tokens than Sonnet 4.6 for the same text. The what's-new page does not identify it as the Opus 4.7 tokenizer. The overview's context note does, calling it "the current tokenizer (introduced with Claude Opus 4.7)", and so does the claude-api skill's `shared/model-migration.md`. Read 2026-09-28.

**Research and specifications**

- [Liu et al., "Lost in the Middle: How Language Models Use Long Contexts" (arXiv:2307.03172)](https://arxiv.org/abs/2307.03172) — the context-ordering rule: performance is highest at the beginning or end of the input and degrades for information in the middle.
- [Zheng et al., "Judging LLM-as-a-Judge with MT-Bench and Chatbot Arena" (arXiv:2306.05685)](https://arxiv.org/abs/2306.05685) — position, verbosity, and self-enhancement bias plus limited judge reasoning; the >80% judge/human agreement figure is specific to those benchmarks.
- [Gao et al., "Enabling Large Language Models to Generate Text with Citations" (ALCE, arXiv:2305.14627)](https://arxiv.org/abs/2305.14627) — citation-quality evaluation, and the finding that the best models lacked complete citation support about half the time on ELI5.
- [Lewis et al., "Retrieval-Augmented Generation for Knowledge-Intensive NLP Tasks" (arXiv:2005.11401)](https://arxiv.org/abs/2005.11401) — the originating RAG framing of parametric plus non-parametric memory.
- [Ragas — available metrics](https://docs.ragas.io/en/stable/concepts/metrics/available_metrics/) — the retriever/generator metric split in section 1. Class names and import paths were not verified against a pinned release; confirm them against the version you install.
- [OpenTelemetry — GenAI client spans](https://raw.githubusercontent.com/open-telemetry/semantic-conventions-genai/main/docs/gen-ai/gen-ai-spans.md) and [GenAI metrics](https://raw.githubusercontent.com/open-telemetry/semantic-conventions-genai/main/docs/gen-ai/gen-ai-metrics.md) — the span and metric contract in section 11, including the normative position that instrumentations should not capture instructions, inputs, or outputs by default. These conventions are at Development status and may change.
- [OpenTelemetry docs — GenAI semantic conventions relocation notice](https://opentelemetry.io/docs/specs/semconv/gen-ai/) — confirms the conventions moved to the `semantic-conventions-genai` repository and that the opentelemetry.io copy is no longer maintained.
- [IETF Internet-Draft — The Idempotency-Key HTTP Header Field, draft-ietf-httpapi-idempotency-key-header-07](https://www.ietf.org/archive/id/draft-ietf-httpapi-idempotency-key-header-07.html) — the idempotency contract: client-generated key (section 7); replay semantics, 409 for an in-flight duplicate, 422 for key reuse with a different payload, 400 for a missing required key, server-defined expiry (trimmed from SKILL.md 2026-09-28). Expired and archived Internet-Draft (rev 07, last updated 15 Oct 2025); never published as an RFC.
